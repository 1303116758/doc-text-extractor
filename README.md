# doc-text-extractor

批量提取 Office 文档文本 —— 扫描一个文件夹，把 `.docx` / `.pptx` / `.xlsx` 的正文和表格内容导出成 `.txt`，并生成一份提取索引。

适用于「几百份文档散在各个项目子文件夹里，需要快速汇总成可检索文本」的场景。提取结果可以继续做关键词统计、全文检索、摘要或向量化。

---

## 功能

- **批量遍历**：递归扫描指定目录，按一级子文件夹分组
- **智能取舍**：按文件名关键词加权打分，优先提取「方案 / 说明书 / 报告 / 成果」类文档，跳过「结算 / 报价 / 模板 / 合同」类噪声
- **多层下钻**：如果某个子文件夹里的 Office 文件特别多，会自动再下钻一层，避免只提取到顶层少数文件
- **表格提取**：`docx` 的表格、`pptx` 的页面文字与表格、`xlsx` 的工作表内容都会写入文本
- **容错**：单个文件解析失败只记录，不中断整批任务
- **索引输出**：自动生成 `index.md`，记录每个源文件提取了多少字、输出到哪个文件

## 安装

```bash
pip install -r requirements.txt
```

依赖：`python-docx`、`python-pptx`、`openpyxl`

---

## 用法

```bash
# 最基本：扫描 ./projects，输出到 ./output
python extract_doc_text.py ./projects

# 指定输出目录，并调整提取数量
python extract_doc_text.py ./projects -o ./output --per-dir 5 --max-files 300
```

### 参数

| 参数 | 说明 | 默认值 |
|---|---|---|
| `input` | 要扫描的文件夹（必填） | — |
| `-o, --output` | 输出文件夹 | `./output` |
| `--per-dir` | 每个目录最多提取几个文件 | `4` |
| `--max-files` | 全局最多提取几个文件 | `220` |

### 输出结构

```
output/
├── index.md                    # 提取索引：哪些文件、各多少字
├── 项目A/
│   ├── 项目A方案设计说明.txt
│   └── 项目A汇报材料.txt
└── 项目B/
    └── 项目B可行性研究报告.txt
```

## 实现要点

几个踩过的坑，写在这里备查：

1. **`pptx` 的表格行不支持切片**
   `shape.table.rows[:15]` 会直接抛异常，必须先 `list(rows)` 再截断。
   早期版本因为这里异常被 `try/except` 吞掉，导致整张表的文字静默丢失。

2. **文件取舍不能只看时间**
   直接取最新修改的文件，很容易取到「结算清单」「模板」这类没有正文的表格。
   改成按关键词加权打分（相关词 +2、无关词 −4、`.xlsx` −1），再以修改时间作为次级排序。

3. **文件多的目录需要下钻**
   有些项目目录把子项目摊平在里面的子目录，顶层只有几个杂项文件。
   当目录内 Office 文件超过阈值（25）时，额外按子目录分别处理。

4. **单个文件失败不能中断整批**
   一个损坏的 docx 不应该让剩余几百个文件全部放弃。
   解析放在逐文件的 `try/except` 里，失败只记进索引。

---

## 已知限制

- 只处理 `.docx` / `.pptx` / `.xlsx`，不支持旧格式 `.doc` / `.ppt` / `.xls`（需先转换）
- `xlsx` 只读前 6 个工作表、每个工作表前 30 行（避免超大表格拖慢整体速度）
- 单个文件文本超过 12000 字会被截断
- 不做 OCR，扫描件 PDF 或图片型文档无法提取
